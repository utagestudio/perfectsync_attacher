# 多言語対応

## 対応範囲

`0.2.0-dev.14`から、日本語（`ja`）、英語（`en`）、韓国語（`ko`）、繁体字中国語（`zh-Hant`）、簡体字中国語（`zh-Hans`）に対応する。ヘッダーの言語メニューで切り替える。

静的な画面文言、アクセシビリティ用のラベル、ページ説明、変換進捗、入力・変換エラー、結果・補足、プレビューの案内と失敗理由を翻訳する。製品名・ARKit識別名・出力VRMの表情名・ファイル名は翻訳しない。

言語切替は表示だけを更新する。処理中のWorker、出力ファイル、プレビューのモデル・スライダー値、開いている補足を維持する。

## 初期選択と保存

1. 有効な保存済みの手動選択があれば、それを使用する。
2. なければ`navigator.languages`を順に調べ、最初の対応言語を使用する。
3. 対応言語がなければ英語を使用する。

中国語は明示的な`Hant`／`Hans`を優先する。指定がなければTW・HK・MOは繁体字、それ以外（CN・SG・地域なし等）は簡体字に対応付ける。日本語・英語・韓国語の地域指定は各基本言語に対応付ける。

手動選択だけを`localStorage`の`perfectsync-attacher.language`へ保存する。保存が禁止されている環境でも切替は利用でき、その場合は再読み込み時にブラウザー設定から選ぶ。モデルや操作履歴は保存しない。

## 実装・追加時のルール

- `src/i18n/locales/`の言語別辞書に同じキーと補間パラメーターを用意する。
- 文言は`textContent`または属性値として反映し、翻訳やパラメーターをHTMLとして挿入しない。
- 静的要素は`data-i18n`、属性は`data-i18n-aria-label`等で指定する。子要素を保持する必要がある場合は文言を専用のspanに分ける。
- 動的表示は`{ code, params }`を保持し、切替時も現在の言語で再表示する。
- エンジンの既知エラーは`AppError`に識別コードとパラメーターを付ける。CLI向けの`Error.message`は日本語、Worker境界ではコードを送る。
- 未分類の例外は翻訳済みの一般エラーにする。ライブラリの生の例外文や入力由来の内容を画面へそのまま表示しない。
- 今後追加する同意ダイアログ等も、同じ辞書・表示方式を使用する。

## 検証と残る作業

辞書のキー・補間パラメーター整合性、言語・中国語地域判定、保存の優先順位と保存失敗を単体検証する。Chromeの操作検証では5言語の自動選択、エラーの再翻訳、結果・52スライダー、状態を保持した切替、再読み込み、処理中の切替、テンプレート取得失敗、プレビュー失敗時の保存、保存禁止時の切替を確認する。

1280×720、390×844、390×640、320×568、844×390で、待機・結果画面と補足展開時にページ全体の縦横スクロールが発生しないことを確認する。長い説明・補足・表情一覧は各領域内でスクロールできる。

翻訳は初稿であり、各言語の自然さ・用語はネイティブによる確認が未実施。Firefox・Safariの実機確認も未実施。

現時点では単一URLのクライアント側切替で、初期HTMLは日本語。言語別URL・初期HTML・hreflang・READMEの翻訳など、検索・公開文書向けの対応は次のREADME・SEO工程で扱う。
