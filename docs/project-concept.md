# プロジェクトのコンセプトとユーザー要件

記録日：2026-10-01

このファイルは、ユーザーが伝えた構想・要件を別セッションでも参照できるように記録するものです。実装上の提案や未確定事項は、ユーザーが指定した要件と区別します。

## ユーザーが伝えたコンセプト

VRoid Studio製のVRMファイルを、ドラッグ・アンド・ドロップするだけでPerfect Syncに対応させるWebアプリを作りたい。

入力したVRMにPerfect Sync用のShape Keyと実際の変形データを追加し、加工済みのVRMファイルを返す。

## 背景と解決したい課題

- ユーザーはVRoid Studio製のVRMファイルを持っている。
- ファイルのVRMバージョンは0.xの場合も1.0の場合もある。
- 既存ツールではUnityを起動して複数の作業を行う必要があり、手間が大きい。
- その作業を、ファイルをドロップするだけの簡単な操作にしたい。

## ユーザーが指定した要件・前提

| 項目 | 内容 |
| --- | --- |
| 対象 | VRoid Studio製のVRM |
| 入力形式 | VRM 0.xおよびVRM 1.0 |
| アプリ形態 | Webアプリ |
| 基本操作 | VRMファイルのドラッグ・アンド・ドロップ |
| 加工内容 | Perfect Sync用のShape Keyおよび変形データの追加 |
| 出力 | 加工済みVRMファイル |
| 公開先 | Cloudflareを想定 |
| 開発の出発点 | 実現可能性の検討と、実現するための設計 |

名前だけのShape Key追加では、変形データも追加したいという要件を満たしません。

## 設計時に提案した方針

以下はユーザーの明示指定ではなく、初回の調査・設計で提案したものです。詳細と根拠は[実現可能性と設計](feasibility-and-design.md)を参照してください。

- Cloudflare Pagesで配信し、変換処理はブラウザー内で行う。
- モデルをサーバーへ送信せず、端末内で処理する。
- 許諾条件を確認したテンプレートから52種類の表情変位を転写する。
- 顔メッシュの頂点対応を検証し、初期は確認できた構造のモデルに対応範囲を限定する。
- VRM 0.x／1.0それぞれの表情定義を追加し、入力の形式を維持する。
- 元GLBを直接編集して、既存の材質・表情・揺れ物設定等の保持を図る。
- 実モデルを使ったPoCで転写品質と利用先アプリの互換性を確認する。

## 未確定・未検証事項

- 対応するVRoid Studioの世代と書き出し設定。
- 改変済みモデルや異なる顔メッシュ構造への対応範囲。
- 採用テンプレートと顔形状差の補正方法。
- 対応ブラウザー、モバイル対応、容量上限、実際の処理性能。
- プレビュー、表情調整、複数ファイル処理等の追加機能。

## 開発開始時の合意・検証環境

- ユーザーは提案した設計での開発を了承済み。
- 動作確認はWebcamMotionCaptureを予定。VSeeFaceも候補として挙げられている。
- 当面はWebcamMotionCaptureを主な検証先、VSeeFaceをVRM 0.xの補助検証先として進める。
- 検証用VRMは`_local/vrm/`に配置済み。ほとんどがユーザー作成のVRoid Studio製モデル。
- ローカル検証用モデルはGit管理対象に含めず、再配布可能な公開fixtureとは区別する。
- 初期PoCのバージョンは`0.1.0-dev.1`。初回の限定機能開発としてminorを1にする。

実モデルによる変換・品質・性能検証は未実施。開発を開始する段階で、公開はまだ行っていません。
