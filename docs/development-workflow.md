# 開発・コミット方針

## ユーザー指定のコミット方針

実装を行う際は、レビューがしやすいよう、小さな単位でこまめにGitコミットしてください。

- 一つの目的・論理的な変更を一つのコミットにまとめる。
- 独立した機能追加、修正、リファクタリングを分け、複数の変更を最後に一括コミットしない。
- 変更に必要なテストや関連文書は、その変更と合わせてコミットする。
- 行数だけを基準に分割せず、レビュー時に変更の意図が理解できる、整合した単位にする。
- コミット前に変更内容を確認し、変更に適した検証を行う。
- コミットメッセージには変更の目的が分かる内容を記載する。

この方針は実装時のローカルコミットに適用します。リモートへのpushは、依頼された作業範囲に従って扱ってください。

バージョン更新と、ユーザー判断後のリリースコミット・push・master向けPR作成は[バージョン・リリース方針](versioning-and-release.md)に従ってください。

masterへのマージは`git merge --no-ff`で行い、マージコミットを残してください。fast-forwardでのマージは行いません。
